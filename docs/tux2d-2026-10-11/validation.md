# Tux 2D 驗證紀錄

Tux 2D 是獨立新增的雪港企鵝卡丁車遊戲，與已發布的 AutoHex 分開提交。雪港環線、車手、道具圖形與 Canvas 向量場景皆由本專案新寫；沒有下載、打包或執行 SuperTuxKart 的程式、音樂、模型、貼圖或賽道。[SuperTuxKart 官方網站](https://supertuxkart.net/Main_Page) 僅作為卡丁車競速玩法的靈感來源，遊戲頁亦標明非官方作品。

本次測試的引擎 SHA256 為 `d136ac5ee7870a17900473d11878c3e7800c5a6a1502c449326300af604ac99e`。引擎使用固定 `1/60` 秒步進，三圈、十二個順序檢查點、五位車手。首度通過起點只啟動計圈，因此完整三圈是每車 37 次通過檢查點，包括最初起跑線一次。

## 規則與回歸

`node --test tests/tux2d.test.cjs` 通過 **21 / 21** 項測試，約 4.89 秒，原始輸出見 [core-tests.log](core-tests.log)。涵蓋：

- 固定步進、倒數與比賽暫停、相同 seed／輸入逐幀一致、重開清除計圈、持有物、投射物、路障、倒數、冷卻及 RNG 狀態。
- 轉向、煞車倒車、雪地減速、甩尾最低速度／蓄力門檻、放開加速、上限與到期。
- 道具按鍵必須重新按下；護盾只擋一次、雪球預備時間、香蕉半秒警告與短暫車主豁免、道具箱七秒補貨、四種共享抽取結果。
- 檢查點順序、逆向與不連續移動不給進度、首次越線不計圈、第三圈結算，以及同一 tick 完賽以車手 ID 穩定排序。
- AI 與人類在相同輸入下使用相同物理；此直接對照刻意停在首次 AI 隨機失誤之前。AI 反向起步以正常煞車、倒車與轉向恢復，不搬移座標。失誤幅度不超過 ±0.18，單次最多觀察到 22 ticks。
- 觀察值隱藏其他車手的持有物；改變敵方隱藏物品不影響自己看到的資料或 AI 決策。AI 以公開危險物與自己的道具決定使用時機。

[獨立審查](review.md) 找到的四類問題均已修正並加入回歸：碰撞推過檢查點漏算、到期道具仍造成命中、出界雪球仍造成命中，以及完全重疊車手無法分離。進度在所有物理位移完成後只結算一次。

## 真實瀏覽器完整三圈

`python tests/tux2d_browser.py` 在 Chromium 1440 × 1000 視窗，以一般前景時鐘完成一場「你 + 4 位 AI」。**這是自動控制器送出真實鍵盤事件，不是人工玩家試玩**：控制器只讀取公開觀察值，透過 Playwright `keydown`／`keyup` 操作方向、油門、煞車與道具；沒有呼叫 `Game.step`、加速虛擬時鐘、搬移座標或改寫圈數。

人類座位完成三圈，模型成績 **48.083 秒、第 3 名**；從倒數結束後至全場完賽共 **52.261 秒牆鐘**，包括一次 0.65 秒暫停。送出 **831 次鍵盤狀態變更**，取得 863 次公開觀察值，逐一確認該車 **37 個順序檢查點、3 次計圈**。五車全部完成，共 185 次通過檢查點、15 圈；本場自然發生 12 次甩尾加速、16 次拾取、11 次道具使用、3 次命中，沒有護盾擋擊。本次完整賽事本身不當作所有道具互動的覆蓋；護盾反制與到期邊界由上述固定測試驗證。

倒數中暫停與比賽中暫停都逐欄確認狀態不變；結果面板可見、重開清空賽事、沒有頁面錯誤或水平溢位。證據：[human-browser.json](human-browser.json)、[執行輸出](human-browser.log)、[完整結算畫面](screenshots/human-result-desktop.png)。UI 來源 SHA256 為 `daab7a3dc186f62a4ee6b7571021e1356b75822290cbe02894b7929e9260523a`。

完整賽事後另修正原生按鈕鍵盤焦點、橫向手機配置，以及保留快速觸控道具點按至下一個物理步。最終 UI SHA256 為 `db2320cb94ca1a312501c41a1bc56d861f28154768cef24510cd5340f66bc2e8`。最終 UI 的九項實際瀏覽器檢查全部通過，包含原生 Space 發車／暫停、恢復後焦點回到賽道、鍵盤護盾、滑鼠與快速觸控道具、重開回到可編輯設定、低動態偏好及頁面載入後離線操作；道具檢查明確使用授予玩家持有物的固定情境。見 [ui-browser.json](ui-browser.json)。上述完整三圈證據屬於明列的賽事 UI 版本；引擎沒有變更。

## 畫面、觸控與瀏覽器成本

[四種畫面驗證](visual-browser.json) 使用桌機 1440×1100、手機 390×844／DPR 3、窄手機 320×740／DPR 2、橫向 844×390／DPR 2。透過實際觸控事件同時按住轉向與甩尾，再放開；六個觸控目標均至少 44 CSS px，賽道與全部按鈕同屏可見。另驗證暫停狀態完全不變、重開清空與停止舊回呼、重開後一秒觀測窗為 59–60 次物理步，以及合成頁面隱藏事件後暫停、恢復可見時仍等候手動繼續。沒有水平溢位或頁面錯誤。這份完整畫面檢查的 UI 是快速觸控點按修正前的 `88bfae2a`；快速點按由前述最終 UI 實測補上。

已實際目視 [桌機全圖](overview-desktop.png)、[手機跟拍](racing-mobile.png)、[橫向手機](racing-landscape.png) 與 [首頁手機入口](catalog-mobile.png)。新圖示在 20／32／48／64 CSS px、DPR 1／2／3 驗證，[DPR 1](icon-dpr1.png)、[DPR 3](icon-dpr3.png) 保留原創向量與負空間；首頁三種寬度均為 15 個可用入口。其他遊戲圖示與規則未變更。

[最終效能記錄](performance-browser.json) 在未加速的 Chromium 前景時鐘中量測實際動畫回呼（包括物理步、畫面與當次 HUD），每種裝置約 12 秒，來源檔案測量前後一致。桌機 715 筆：中位數 1.0 ms、P95 2.7 ms、最大 31.8 ms；手機模擬 612 筆：中位數 1.2 ms、P95 4.0 ms、最大 438.4 ms。畫面間隔中位數皆約 16.7 ms，P95 桌機 16.7 ms、手機 33.3 ms。

## 保留 seed 的完整 AI 賽事

`node tests/tux2d-study.cjs docs/tux2d-2026-10-11/races.json 36 101` 使用先前開發試跑之外的 **36 個 seed（101–136）**，每場讓五位 AI 跑完整三圈。這是 **加速固定步進的 Node 模型模擬**，不是另外 36 場真實時鐘或人工玩家試玩。引擎 SHA256 與上述固定測試／完整鍵盤賽事相同。

**36 / 36 場完成，180 / 180 車完賽**；共 540 圈、6,660 次順序通過檢查點，累積 1,996.37 模型秒（含每場三秒倒數）。車手成績範圍 47.35–55.52 模型秒，整批花費 72.05 秒牆鐘；此為共享測試環境的執行成本，不當作終端裝置效能保證。每 tick 檢查數值有限、圈數不跳躍、位移連續，以及事件／雪球／香蕉數量上限；每車精確通過 37 次檢查點。

累計 540 次甩尾加速、666 次拾取、538 次道具使用、88 次命中、29 次護盾反制、2,814 次車碰撞；零次撞牆、零次恢復計數。最大連續低速（速率小於 10）為 0.317 秒；單次 AI 誤差最多 22 ticks。完整統計與每場來源／軌跡摘要見 [races.json](races.json)，逐場輸出見 [races.log](races.log)。

固定車手設定下冠軍分布為 Nova 27、Pip 6、Tux 3，Mochi 與 Sunny 沒有冠軍。這說明本次 seed 的實際結果集中在較快的設定；**不是均衡勝率的證明**，也沒有用抽取隱藏道具、瞬移或專屬物理加成補償 AI。
