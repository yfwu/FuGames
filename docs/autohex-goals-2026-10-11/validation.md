# AutoHex 對岸優先修正：驗證紀錄

本輪固定候選在 72 組配對條件中，對岸到達次數全部高於已發布版本；曾完成連線的玩家比例由 28.7% 提升至 88.4%。機場也不再是大多數首次連線的前置條件。這支持「以對岸為主、航空為支援」的改變，但沒有證明勝率平衡或全圖均勻交戰：中央戰鬥更密集，最大領先差也擴大。

比較基線為 commit `f3d50e73a8bbb90ee4eda2b6386b4cac98939446`，引擎 SHA256 `a75d8a8fe9c372921f1937a7e4d5b40e438642a07a6f6979ea30154304a5fb26`。固定候選 SHA256 為 `a029f76bb5424506a21f8485519176f010c3803aed401a20733ad83aaf4c9f09`；保留樣本開始後沒有調整引擎。動態機場、地形可達性與 AI 修改一起比較，不能把差異全部歸因於 AI 單一因素。[規則與生成方式](rules.md) 說明了保留的戰鬥、資源及計分規則。

## 樣本與時間

正式樣本是 **六個獨立 seed**：`1601,1709,1801,1901,2003,2101`。每個 seed 採六種性格輪替，分別執行兩種起手偏移，共 **72 種設定／版本、144 局**，不是 72 個獨立 seed。兩個區塊的先手公式分別為 `(rotation + offset) % 6 + 1`，`offset` 為 0 或 1。合併後每個 seed 的各座位、各性格各先手兩次；整體各先手 12 次。腳本斷言這些邊際計數，並核對前後版本的完整配對條件。這仍不是所有輪替與先手組合的完整交叉實驗。

第一區塊單獨只有三種性格會先手；因此保留原始結果，再增加第二區塊補齊，正式結論使用合併資料。另有兩組互不重疊的開發樣本：獨立測試者的 `211,307,401,503,601,709`，以及引擎作者的 `17,29,43,61,83,107`。兩者均未併入正式保留樣本。

每局完整執行 2,000 個合法 AI 行動，每手推進 300ms 模型時間，直到 600,000ms 結束。合計 288,000 手、24 小時模型時間。這是加速模擬；實際瀏覽器十分鐘驗證另列。每 100 手檢查 96 張實體牌守恆、手牌上限、永久家園與非負資源；逐局核對完成狀態及事件重建的到達／持有次數與引擎計數相等。全部通過。

四個區塊的程序耗時如下，曾共享 CPU 並行執行，不能相加當作整體經過時間或裝置效能基準。

| 區塊 | 基線程序秒數 | 候選程序秒數 |
| --- | ---: | ---: |
| 起手偏移 0，各 36 局 | 553.07 | 488.16 |
| 起手偏移 1，各 36 局 | 443.55 | 378.45 |

每一組配對的到達次數均增加，增幅範圍為 5–32，平均增加 16.22 次。兩版都曾連線的相同 seed／座位／輪替／先手玩家場次共有 109 組；首次時間平均提早 112.1 秒、中位數提早 108.0 秒。這個配對比較避免直接把不同成功玩家集合的首次時間平均當成同一群人的改善。

前沿進度是「36 減去家園補給中的己方棋子到指定對岸的最小軸向距離」，每完整輪抽樣。路徑缺口以獨立 0/1 圖搜尋計算：從任意家園補給中的己方棋子走相鄰格到對岸，計算最少非己方格數；排除敵方永久家園，不計地形、能量、盟約和即時可行動性。每 30 手抽樣，所以最高進度與最小缺口可能漏掉短暫狀態；到達與持有則在實際計分邊界逐次記錄。

機場使用減少且更常與路線進展一起發生。候選仍有 185 次有補給空投，以及 892 次來源明確的後續空投炮台命中；六個 seed 都至少有一種輪替設定使用航空。38 局沒有航空動作，符合設施可選的目標。未立即前進的建設可能有防守價值，這個指標不等於浪費。

候選航空行動結算前後，觀察到 131 次己方前沿改善、150 次己方缺口減少、111 次敵方前沿後退、86 次敵方連線由通變斷。這些項目可以重疊，而且涵蓋完整合法行動結算，包括維持、輪末與下一位玩家自動炮擊，**不能當成每發航空攻擊的單獨因果歸屬**。獨立戰術 fixture 另驗證了遠距轟炸確實切斷敵方家園至對岸供應線，與己方已連線時的有補給防守空投選擇。

## 中央、過渡與外側活動

區域依六角格中心半徑分為中央 0–6（127 格）、過渡 7–11（270 格）、外側 12–18（630 格）。戰鬥計數為占領／摧毀事件涉及的格次，含自動炮擊；換位可涉及兩格。密度除以實際格數及對局數，避免面積較大的外側僅因格數較多而占優勢。

| 區域 | 戰鬥格次／格／局，前→後 | 平均被占領比例，前→後 |
| --- | ---: | ---: |
| 中央 | 0.221 → 4.704 | 10.68% → 59.94% |
| 過渡 | 1.502 → 1.277 | 37.46% → 27.64% |
| 外側 | 0.955 → 0.203 | 27.30% → 11.54% |

候選的中央交戰明顯集中，不能宣稱全圖活動均勻。移除外圈設施先決路線後，六方對岸路線在中央相交；資料同時顯示真正連線與持有增加。是否喜歡這種集中程度仍是玩法取捨，不應再只為壓低中央密度而犧牲主要目標。引擎作者的開發報告使用不同區域邊界（0–6／7–9／10–18），其原始區域數字不可與本表混用。

每局最後 500 手，戰鬥格次範圍由 236–343 變成 193–335；棋盤變動格次由 509–703 變成 572–751。候選最後四分之一合計 36,000 手中有 35,961 手不是休息或棄牌（研究腳本的活動代理指標）、30,450 次部署、461 次到達、2,939 輪持有、135 次航空，休息 0 次。後段戰鬥格次合計為 19,804 → 20,707，約增加 4.6%。這些樣本沒有靠長時間休息湊足時鐘。

## 規則與瀏覽器驗證

[完整 Node 紀錄](node-tests.log) 為 **313/313 通過、0 失敗**，耗時 258.65 秒。包括原有遊戲、AutoHex 規則及 Tux2D 回歸。動態機場的既有戰略／視覺 fixture 改用當局公開座標，保留航空射程、資源、冷卻、上限與斷補測試；針對這兩檔的 [25/25 紀錄](migrated-tests.log) 亦通過。新增策略測試覆蓋 48 個 seed 的布局／六重對稱／可達性，以及具體連線、修補、敵方得分線防守和隱藏資訊不影響決策。

[桌面與手機瀏覽器紀錄](browser.json) 使用受控 fixture 與虛擬計時，驗證換 seed 後機場導航跟隨當局座標、透過 UI 航空操作、非法操作原子性、無機場也能連線／持有計分、重播重設、旁觀手牌隱藏及無溢出。這些是互動與呈現測試，並非完整自然對局。

整合工作者另以固定候選、原始預設 0.30 秒節奏，執行 [實際前景 Chromium 對局](live-final/live-browser.json)，完整經過 **600.627 秒**，活動時計到達 600,000ms。沒有虛擬時間，來源 hash 全程不變，沒有頁面或 console 錯誤；[執行備註](live-final/execution-notes.json) 記錄共享 CPU 狀況。實際完成 1,509 手而不是模型研究的 2,000 手，因此兩者不可當成相同行動預算比較。

該實際對局有 619 次占領、126 次摧毀、292 次斷補退場、121 張牌使用、9 次對岸到達、7 輪連線持有，六方中五方曾連線。第十分鐘仍有 179 手、209 格變動、87 次占領與 17 張牌。機場啟用與失去各 3 次，沒有航空動作；航空互動另由 UI fixture 與多 seed 模型研究驗證。最終兩方以 152 分同列第一。這是單一桌面瀏覽器樣本，不能保證每個 seed、裝置或實體手機都同樣流暢。

## 重現與原始資料

[獨立研究腳本](../../tests/autohex-goal-study.cjs) 是手動執行的 `.cjs`，不加入一般 `.test.cjs` 測試 glob。它在執行前載入完整來源並記錄 SHA256，候選來源保存在 JSON 中；基線使用完整 Git commit。下列命令需在包含該基線 Git 歷史的倉庫執行，候選檔也需與上述固定 SHA 一致。

```sh
node tests/autohex-goal-study.cjs --mode baseline --sample heldout --output docs/autohex-goals-2026-10-11/baseline-heldout.json
node tests/autohex-goal-study.cjs --mode candidate --sample heldout --output docs/autohex-goals-2026-10-11/candidate-heldout.json
node tests/autohex-goal-study.cjs --mode baseline --sample heldout --first-offset 1 --output docs/autohex-goals-2026-10-11/baseline-heldout-offset1.json
node tests/autohex-goal-study.cjs --mode candidate --sample heldout --first-offset 1 --output docs/autohex-goals-2026-10-11/candidate-heldout-offset1.json
node tests/autohex-goal-study.cjs --merge docs/autohex-goals-2026-10-11/baseline-heldout.json,docs/autohex-goals-2026-10-11/baseline-heldout-offset1.json --output docs/autohex-goals-2026-10-11/baseline-heldout-combined.json
node tests/autohex-goal-study.cjs --merge docs/autohex-goals-2026-10-11/candidate-heldout.json,docs/autohex-goals-2026-10-11/candidate-heldout-offset1.json --output docs/autohex-goals-2026-10-11/candidate-heldout-combined.json
node tests/autohex-goal-study.cjs --compare docs/autohex-goals-2026-10-11/baseline-heldout-combined.json --candidate docs/autohex-goals-2026-10-11/candidate-heldout-combined.json --output docs/autohex-goals-2026-10-11/comparison-heldout.json
```

[正式配對比較](comparison-heldout.json)、[合併基線](baseline-heldout-combined.json)、[合併候選](candidate-heldout-combined.json) 保存各局行動 trace SHA、時間線、每位玩家進度、得分、勝者、航空用途與分期活動；各原始區塊及 `.log` 也保留。可只執行最後三行重新核對／合併已保存資料，不必重跑戰局。兩組開發比較分別保存在 [獨立開發比較](comparison-development.json) 和 [引擎作者開發比較](development-engine-comparison.json)，後者另有 [可攜式重跑腳本](development-replay.cjs)。正式結果沒有混入開發樣本，也沒有沿用舊版真實十分鐘證據。
