# AutoHex 外圍戰略與棋盤辨識

本輪從已發布的 `13c94a8a98395fcb59289e28e72ad5a09374904c` 接續。既有原版三方 Hex 與另外十二款遊戲未改動。新的 AutoHex 策略規則不是原版 Hex 的選項。

## 公開棋盤

- 炮台有砲座、炮管、陣營字母與射擊倒數；全圖最小 12 CSS px。查看模式不會出手，點炮台顯示三格射程及當下可攻擊的公開敵子。標靶不是保證下一發命中的預告。
- 炮擊軌跡來自真正結算事件的出發格；拆除只有命中效果，不捏造發射位置。護盾吸收、棋子崩解與斷補撤退各自可辨。崩解不會刪除地形格。
- 補給顯示從家園出發的一棵連接樹（不是全部可能路徑），可查看全部、單一陣營或關閉。斷補棋子改用空心虛線與剩餘撤退倒數。
- 效果使用同一前景時鐘，暫停／隱藏頁面凍結，重播／重開清除，最多 64 個效果與 256 個去重 ID。減少動態偏好改用靜態命中標記；動畫不阻擋 AI。
- **AutoHex 沒有陷阱或戰場迷霧。** 未新增虛構陷阱視覺。原版 Hex 的己方暗伏範圍仍只對自己顯示；觀戰不顯示任何未揭露陷阱。

## 外圈設施與反制

六座公開機場位於半徑 12 的六個頂點方向，六座補給站位於半徑 10 的六個側邊方向；各方起點對稱可達，設施地形保證通行。對岸補給連線仍是主要計分目標。

機場中心必須屬於自己、連回家園，且四格內有至少 12 格與中心相鄰連成一片的己方領地；連續三個完成的己方行動達標後啟用。局部連片不以橋梁冒充相鄰面積。中心失守、家園補給中斷或面積不足，能力立即失效且重新累積進度。

物資與每回合恢復的能量分開：物資上限 6，每三個完成的己方行動補 1；若持有至少一個有家園補給的補給站，該次再補 1。多個站不疊加，因此搶站可加快行動但不會無限放大資源收益。機場本身不提供被動分數或攻防加成。

| 行動 | 條件與成本 | 作用與反制 |
| --- | --- | --- |
| 空投炮台 | 先選啟用的己方機場，再選十格內空的可通行地格；6 能量、3 物資 | 放入棋子及炮台，仍受每方 96 子／3 炮台上限；未接補給仍會在六次己方行動後撤退 |
| 遠程炮擊 | 先選啟用的己方機場，再選十二格內非盟友、非家園敵子；7 能量、4 物資 | 護盾吸收一次，否則摧毀一子；無範圍傷害 |

兩種空中行動共用六次己方行動的冷卻，無需抽到新牌。**只有這兩種行動可超出通常「既有己子五格內」的選點限制**，距離從所選機場計算。可攻擊機場、區域邊緣或後方補給線來關閉能力。

## 持有年齡與中立事件

新放置、攻占或換位後的棋子持有年齡為 0；之後每完成一次仍保持同一所有權的己方行動才加 1。**第 31 次才固守（嚴格超過 30），不是全場 30 手，也不把放入當手算作已守一回合。** 固守只免疫中立游擊／災害；敵方直接攻占、拆除、炮台、遠程炮擊，以及斷補撤退仍有效。

AutoHex 原先沒有中立游擊／災害；本輪新增可關閉、預設開啟的有界事件。每 12 輪一次，提前兩輪公開區域與最多兩個目標格，按獨立 seed 序列輪換區域，交替游擊與災害。只影響公開已佔領的非家園格，不讀人類身分或隱藏手牌；結算時固守免疫、護盾吸收，否則移除棋子，地形保留。不增加額外回合、不延長十分鐘戰役。

## 驗證紀錄

最終程式通過 **284 / 284 Node tests**（`node --test --test-concurrency=2 tests/*.test.cjs`，210.23 秒）；其中 31 項新增測試包含設施失守、資源守恆、距離／冷卻、31 回合門檻、交換重置、固守不擋敵方直攻／斷補、中立事件獨立 RNG、同分結算、AI 三種具體戰術與隱藏資訊。

瀏覽器驗證包括 1440px 桌面、390px / DPR 3、320px / DPR 2 與橫向手機；真實點按測試空投、遠程炮擊、所有既有牌、外交、非法橋線／空中目標不扣資源、暫停、速度變更、單步、切頁、重開與 seed 重播。手機另完成 60 次人類操作、355 手，實際用到空投；雙指縮放與結算後自由續玩通過。公開棋盤不受敵方手牌／牌堆排列影響；原版 Hex 顯示 7 格己方暗伏範圍，敵方暗伏變動不改畫面，觀戰隱藏全部未揭露暗伏。

[十分鐘前景實測](live-browser.json) 使用固定預設每步 0.30 秒，沒有虛擬時鐘：**600.65 秒牆鐘 / 600,000ms 活躍時間 / 1,251 次行動**（約 2.08 手/秒）。最後一分鐘 117 手、119 次格子變化；整局 15 次機場啟用、15 次失效、10 次空投、8 次轟炸，1 次對岸接通。沒有切背景、console error 或 page error；五個來源檔 SHA256 全程不變。定期取樣最多 4 個活躍效果、去重集合最多 256。這是實測步速，不是每分鐘百萬局的效能承諾。

[晚局效能](performance-browser.json) 在 1,998 次加速模型行動、599,400ms 模型時間後測 30 次真實 `performance.now()`：桌面同步 render 中位數 34.0ms／p95 54.0ms，手機視窗 19.7ms／p95 75.2ms；觀察值加 AI 中位數分別 7.0ms／4.8ms。手機視窗有一次 672.5ms render 峰值及 99.4ms AI 峰值，原始數據保留；不能據此保證低階實體手機幀率。較早與多個研究並跑的高負載紀錄另存 [loaded benchmark](performance-loaded-browser.json)。`render` 計時不包含之後的 compositor 工作。真實時鐘慢 AI／過期 RAF 回歸漂移 −46ms，暫停時間凍結。

`before-browser.json` 與 `screenshots/before-*` 由 Git 基線資源路由取得，沒有重設工作目錄。已目視代表性的 before/after、雙重炮擊、全圖／局部、320px 與 390px 手機圖。

歷史 `engine-equivalence.json` 僅證明新增公開視覺事件 metadata 的中間版本維持原行為；不代表本輪加入機場與固守後仍與舊規則等價。最終策略使用另外的 before/after 多 seed 對照。


## 保留 seed 的策略對照

[完整報告](strategy-report-heldout.md)／[結構化結果](strategy-summary-heldout.json)：六個未參與調整的 seed，各六種先手及性格輪替，基線與新版本各 36 局，每局 2,000 次合法行動，合計 144,000 手。來源版本在保留樣本前固定，沒有依該樣本調整 AI。

| 指標 | 基線 | 本輪 |
| --- | ---: | ---: |
| 中央／外圈每格戰鬥密度比 | 5.66 | 0.195 |
| 外圈占全部戰鬥比例 | 39.6% | 86.1% |
| 對岸接通次數 | 79 | 106 |
| 至少接通一次的局數 | 27/36 | 31/36 |
| 每局末四分之一戰鬥影響格數 | 284.4 | 272.6 |
| 平均最終前兩名分差 | 9.89 | 16.08 |

本輪實際出現 1,085 次機場啟用、1,022 次失效、827 次空投、348 次轟炸；同座設施重新啟用會再次計數。每局最後四分之一仍有航空行動，全部 36 局在六個扇區皆有戰鬥。中央沒有禁建或禁攻規則，AI 因外圈設施與側翼路線價值改變選擇。

**限制：** 戰鬥現在明顯偏向外圈，並非各處平均。每方空間行動跨扇區數從 5.33 減至 4.66，持續守住對岸的輪數由 233 減至 163；平均最終分差反而增加，最終最大分差 60，不能宣稱已消除滾雪球或證明平衡。性格勝場在此樣本為 5–7 場，但樣本有限。對照一次涵蓋設施、AI 與中立事件，不能把變化單獨歸因給某一功能。沒有勝負指定、落後加分或身分資源補貼。

公開 GitHub Pages 的瀏覽器連線仍被此環境代理阻擋（`ERR_TUNNEL_CONNECTION_FAILED`）；本機 Chromium 已驗收，但不宣稱完成公開站 online browser 驗收。發布以指定 commit 的 GitHub Actions 與 Pages deploy 終態為準。
