# AutoHex：六方大型戰役

AutoHex 是新增的第十四款獨立遊戲，入口為 `autohex.html`；原版 `card_hex.html` 與其三方規則保留。所有計算在本機瀏覽器完成，沒有網路多人或帳號系統。

## 預設與規則

- 半徑 18 的六邊形，共 **1,027 格**。六方各有一個永久家園及兩枚起始棋子，從自己的邊中央前往對側 19 格邊線；相對兩方共享一條軸，但方向相反。
- 預設一人加五 AI，也可選六 AI 觀戰。AI 每步 **0.30 秒**，可調 0.05–10 秒。戰役計入 **600,000 毫秒前景、未暫停的真實時間**；人的思考時間計入，準備／暫停／背景不計入。切頁自動暫停，回來須手動繼續。單步不增加戰役時間。結束後可選不限時自由對戰。
- 鋪子及所有空間卡牌目標，必須在行動前距離最近的**自己既有棋子五格內**。盟友、敵方或其他標記不延伸範圍。遠端自己的棋子本身仍可作橋端點；橋不會憑空放置遠端棋子。
- 地形由 seed 產生且六重旋轉對稱。河流先花一回合築路，所有人都能利用道路；山丘增加一點奪格防禦，並非一次性護盾。家園附近先清出平地，築路不依賴抽牌。
- 補給由家園沿自己相鄰棋子及自己的橋傳遞。斷補後仍可出手，第六次自己的行動結束時尚未接回才撤退。每方上限 96 子；撤回騰出空間並回復一能量。家園不能被摧毀或奪走，因此可重建。
- 初始能量 5，每次自己回合開始加 3，上限 8。空格鋪子 2、奪格 4、築路 2；每回合只做一件事。奪格要求相鄰己子與附近己方炮台支援達到防守值；防守為基本 1、山丘加 1、護盾加 2，另加有上限的相鄰守軍支援。
- 共用 **96 張實體牌**，六種各 16 張。每方開局五張、手牌上限五張，用牌／棄牌後才補到上限；抽牌池用盡才洗回棄牌。沒有依排名、人類身分或 AI 名稱補貼抽牌。

| 卡牌 | 能量 | 行為 |
|---|---:|---|
| 炮台 | 4 | 強化已有己子；射程 3，每三次自己回合射一個非盟友目標，壽命 30 次自己回合，每方最多三座。 |
| 拆除 | 5 | 移除範圍內敵子；護盾先吸收一次，家園免疫。 |
| 橋梁 | 3 | 連接兩枚距離 2–5 的已有己子，傳遞補給；可跨河。 |
| 改接 | 2 | 選保留橋端、舊端、新己方端點，替換自己的一座橋。 |
| 護盾 | 2 | 保護己方非家園棋子八次自己回合；增加奪格防禦，吸收一次拆除或炮擊。 |
| 換位 | 3 | 己方普通棋子與相鄰空格／非盟友普通敵子交換；家園、炮台及橋端點不參與。 |

橋梁共用精確的幾何合法性：任何 owner 的既有橋都會阻擋重複、反向、部分重疊、穿越與 T 字接入；真正的共同端點可以連接。人類與 AI 經過同一個 `legalAction`。非法選點不扣牌、不花能量、不消耗回合。

每六次行動後，**同時檢查六方**：首次有補給的對岸連線得 12 分；連續守住每輪 2 分；失去後重接須距上次獎勵至少 12 輪，得 6 分。接通不提前結束戰役。奪格／摧毀敵子另得 1 分。時間到時按已有分數共同排名，未完成的最後一輪不額外結算路線；同分共享第一，不以先手或盟友身分裁決。

## 外交與 AI

提議、接受、拒絕、背盟各占一回合。提議三輪到期、發起冷卻八輪；停戰十二輪，每方最多兩盟友。盟友仍各自計分、不分享私牌；炮台不會暗中攻擊盟友。背盟先付一回合、三能量、四分、兩聲譽，並產生十八輪交涉冷卻及雙方怨恨，之後才可攻擊原盟友。

六種 AI 使用共同公開路徑與戰術評分，分別偏向先鋒、工程、防守、襲擊、外交、尋路。`rotation` 只輪替策略，不變更家園、地形、牌池或資源。AI 依公開分數、接壤前線、共同威脅與路線阻擋判斷外交；没有指定勝負的補分。決策僅接收本方 observation，私手與牌堆順序不外流；觀戰介面使用 observation(0)。

開發初版兩個種子雖持續戰鬥，卻沒有對岸連線；提升路線推進的公開評分後才固定引擎跑正式研究。這是開發調整，未把早期失敗批次混入正式結果。此版仍以大量局部奪格為主，接通不是每局必然發生，策略也不保證最優或均衡。

## 驗證資料

正式引擎 SHA256：`b9f70d993c417964899feea6dbd7cc2bd971d524a7a3fd048a5b9948f0f57cdb`。

**253／253 項回歸全數通過**：原 227 項保留，新增 AutoHex 頁面整合一項、獨立規則 25 項。範圍包括六方向、五／六格邊界、所有卡牌、牌守恆與重洗、橋線衝突、補給退場與救回、盟約到期／背叛／炮台免傷、六方共同計分及平手、重開／時鐘、同 seed 重播、敵方私牌改內容不影響 observation 或 AI。首頁契約精確改為 14 遊戲／39 個 SVG symbol；舊共用 shell 測試容許同一元素增加 CSS class，仍要求全部共用 class。[完整回歸紀錄](regression.log)

同 seed 的六次輪替彼此相關，不能把 144 場視為 144 個獨立地形。六種策略都有勝場，但工程與外交勝場仍相差超過一倍，此樣本不能證明平衡或循環互剋。後期大量反覆邊境奪格是已知限制；有棋盤活動不等於每步都有不同戰略，且部分場次末段完全沒有用牌。所有權移轉統計會將敵方換位的兩格都計入，與引擎計一次換位奪格的 telemetry 不同。沒有使用人為勝負加分修飾結果。

### 真實十分鐘預設節奏

seed `autohex-live-2026-10-11`，1440×1100 Chromium，預設每步 0.30 秒：**600.37 秒牆鐘、600,000ms 活躍時間、1,833 次行動、305 個完整輪次**。沒有安裝虛擬時鐘、沒有手動增加 activeMs、沒有切背景；引擎／UI／HTML／CSS 四個檔案的 SHA256 從起跑到結束完全相同。零頁面或 console error，C 紫藤以 147 分勝出；本局有一次對岸接通。

六張卡實際使用：炮台 29、拆除 2、橋梁 26、改接 11、護盾 23、換位 28；築路 76 次，提議 16、接受 4。**最後一分鐘仍有 187 次行動、171 次棋格變化，124 枚原有棋子遭移除或交換所有權**，其中也包含撤回及供應退場，不把它全算成戰鬥擊殺。該分鐘用了八張卡，並非單靠延長等待時間維持戰役。

平均實際吞吐為 **3.05 手／秒**，包含 0.30 秒 pacing 與瀏覽器運算／渲染。這一局是預先選定的實跑案例，不代表所有 seed 都有相同結果；上述 144 場模擬另檢查跨 seed 活動。[逐分鐘實跑資料與来源 hash](live-browser.json) · [五分鐘戰況](screenshots/live-mid-desktop.png) · [十分鐘結算](screenshots/live-result-desktop.png)

## 重跑

```sh
node --test tests/*.test.cjs
python -m http.server 8011 --bind 127.0.0.1
```

另一個終端執行 `python tests/autohex_browser.py`、`python tests/autohex_player_browser.py` 或 `python tests/autohex_clock_browser.py`。`python tests/autohex_live_browser.py` 使用真正的前景時間，必須實際等待至少十分鐘；不會安裝虛擬時鐘。研究配置與 seed 保存在 `study-a.json`、`study-b.json`，摘要腳本為 `tests/autohex-summary.cjs`。

公開站瀏覽器仍被此環境代理阻擋（`ERR_TUNNEL_CONNECTION_FAILED`），因此本機 Chromium 驗收與 GitHub Pages 部署狀態分別報告，不宣稱已在線上 browser 驗收。
